# 001 — Historical baseline audit (development only)

From the repository root, run `python3 agents-collab/results/001-baseline-audit/audit.py`. Python 3 standard library only. The script reads the full archived t310 CSV and rank partition CSV; it does not import the experiment code, generate graphs, run dynamics, or open a new confirmation sample. `--out DIRECTORY` writes the tables elsewhere.

**Scope:** Audit §1 of `agents-collab/연구계획.md`: compare the implementations and archived samples, reconstruct all 48 t310 graph rows, tabulate graph-paired ARI differences and failure denominators under historical and plan scoring, and identify what the archives cannot recover. No scientific interpretation is made here.

Rank calibration is separate from those 384 records: `dev_specs` has 18 connected positives (24+24, unit bridges, b=1/2, seeds 0–2) and six negatives (ER/rewired, seeds 10–12). Its hold statistic uses length-50 windows at stride 25, not the edge-cut scoring window. The calibration and stimulus/stability archives are not additional partition graphs. The shared graph builder and cutoff do not establish pairing: the complete `(family, sizes, bridges, weight, seed)` keys do not overlap, the rank sample has a different design mix, and initialization, wave speed, tested forces and reported failure treatment differ. Even if deterministic graph topologies repeat, they are not recorded matched trials. Keep the datasets separate rather than letting the larger rank sample dominate a pooled estimate.

## Failure and scoring audit

Both implementations flag a run on the first updated frame where *not all* `abs(u) < 20` (`rank_experiment.simulate`, `wave_test.simulate`, and `common._loop`). Thus exactly 20 and nonfinite values fail too, despite the old prose using `>20`. Failed states are zeroed from that frame; the entire run, including its valid prefix, is excluded from partition scoring. Some other t310 diagnostics use valid prefixes, but not ARI. Run fractions divide by all eight initializations, not survivors; graph failure means at least one of eight failed. Rank raw/LP variants of the same wave share the failure count and should not be added together as separate runs.

- `legacy_available`: archived ARI unless missing. The rank report averages available graph scores: completely failed graphs have missing ARI; partially failed graphs use the survivors. In t310 this corresponds to the available-case summary (e.g., `ARI_cond_edge_cut`).
- `legacy_report`: t310 `a310.py` uses `fillna(0.0)` for the main ARI table and paired tests, retaining partial-run graph scores. This also imputes any missing readout, not only all-failed rows; in this archive both edge-cut scores are present exactly when at least one run survives.
- `plan`: retain every graph in the denominator and replace that method's entire graph score with zero when `n_ok<8`, independently for each method, before subtraction. This applies the plan scoring rule to the historical failure flags, not a fresh threshold pass. Spectral is unchanged across readouts and policies. Its source row uses `n_ok=1` as a placeholder and has no `R`; it is not counted in run/graph failure summaries.

For the nine requested methods, only `huber_local` wave has failures: 69/384 runs, affecting 30/48 graphs (all partial). Legacy therefore retains all 48 graph scores for this method; the plan replaces 30 scores with zero in each readout. Raw mean changes 0.3290 → 0.2163, LP 0.8256 → 0.3653. The other eight methods have 0/384 run and 0/48 graph failures each. `t310_failures.csv` also covers the other 51 recorded methods.

## Outputs and validation

- `t310_graphs.csv`: 48 unique graph IDs; metadata, spectral ARI, and the nine dynamic configurations' `n_ok`, `R`, failure fraction and raw/LP scores under all three policies.
- `t310_pairs.csv`: 288 unique graph × readout × comparator rows. Difference is `huber_local` wave minus Mean wave, same-force diffusion, or spectral; both endpoints use the same readout and policy except that spectral is fixed.
- `t310_pair_summary.csv`: unweighted means of the graph-level differences. Denominators are 48 overall, 16 per family, 12 per bridge count; both eligible graph counts and actual observed pairs are reported.
- `t310_failures.csv`: run and graph counts/rates, partial and all-failed graph counts, per-readout means and denominators, and plan minus historical-report mean differences, in the same strata.
- `rank_historical.csv`: archived connected-positive partition means, available graph counts and dynamic failure counts overall/by family. Baselines have no eight-run denominator.

The script checks exact key coverage (48 × [60 dynamics + 1 spectral] = 2,928 rows), row metadata against IDs, valid ARIs, spectral layout, and `fail_frac=(R−n_ok)/R`. For rank it validates 6,720 unique method rows covering 424 graph specs (384/24/16 by role), positive dynamic failure counts in eighths, and zero positive graph-key overlap with t310. The headline historical ARIs reproduce to reported precision: rank spectral/Mean diffusion/Mean LP wave 0.814/0.827/0.679; t310 spectral/Mean LP wave/fixed Huber LP wave 0.829/0.752/0.521.

**Archive limits and report discrepancies.** Neither archive contains trajectories, per-init ARIs, or identities of failed initializations. A median-edge cut cannot be decomposed into per-init ARI; neither prefix-based scores nor a changed threshold/filter can be reconstructed from these summaries. In the rank report, “only clique survived” is not literal: LP Trim has ARI for 160/384 graphs, including 32/128 cycle graphs (all partial; 948/1,024 cycle runs failed). Its LP ARI of 1.00 is an available-case mean, not a full-sample score. The reported disconnected-control ARI of 1.00 is only an available-case statement where scores exist, not an all-methods/all-graphs result: e.g., OWA and Value-weight wave have no available disconnected-control ARIs. Rank hold/arrival columns store graph-level aggregates, not per-window or per-run records; the old prose does not always specify the denominator (e.g., counting a missing hold as false versus dropping it). This audit does not rerun or try to reverse-engineer those individual observations.
